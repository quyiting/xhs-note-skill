# 首图规范 · 两种策略

## 设计前提

小红书信息流里首图只有约 150px 宽。首图的唯一目的不是好看，是**让人在缩略图里读懂**。

**选哪种策略由账号档案决定**（`visual.image_mode`）。一旦定下，同系列内不要一篇一换 —— 风格飘忽本身就是掉粉原因。

---

## 零、先判断一件事：主体是「物」还是「人」

这一步决定后面所有选择，比画风重要得多。

| 主体 | 例 | 能不能 AI 生成 | 为什么 |
|---|---|---|---|
| **物** | 一杯酒、一道菜、一件衣服的平铺、工具、产品、书、代码界面 | ✅ 可以 | 没有身份，不承诺「真人体验」 |
| **人** | 上身效果、化妆前后、健身动作、真人出镜口播 | ❌ 必须实拍 | 卖点就是真实身体与真实结果，AI 恰好毁掉它 |
| **混合** | 穿搭（上身图 + 单品图）、美妆（上脸 + 产品） | ⚠️ 拆开做 | 上身/上脸实拍，单品/平铺可生成 |

> **判断口诀**：读者要看的是「**这东西长什么样**」还是「**我用了会怎样**」。
> 前者 AI 可以，后者只有真人可信。

把人做进 AI 图里，还会额外踩三个坑：人设跨篇不一致、平台对 AI 人像有标注要求、品牌合作要求真实穿着/使用。

---

## 策略 A：纯照片（默认）

**首图 = 一张生活感照片，图上不加任何文字。**

卖点全部由标题承担。这是被验证过最省事、最不容易翻车的形态，也是「AI 味」最轻的形态。

```
┌──────────────────────────────┐
│                              │
│                              │
│      [ 一张真实感照片 ]        │  ← 唯一主体，占 55%–70%
│       有方向的光 / 真实阴影     │
│       台面有水渍、指纹、杂物     │
│                              │
│                              │
└──────────────────────────────┘
   文案：全部放标题，图上 0 字
```

### 硬性规范

| 项 | 规格 |
|---|---|
| 尺寸 | 3:4（1242×1656 或 1080×1440） |
| 图上文字 | **0**（不加卖点、不加角标、不加名称、不加边框贴纸） |
| 主体数量 | 只一个 |
| 光 | 单一方向光源，有可辨认的阴影 |
| 桌面 | 2–3 件与主体无关的杂物（餐巾、砧板、纸巾、水果、瓶子） |
| 不完美 | 留一处「不干净」：水圈、指纹、汁渍、边缘杂物 |
| 禁止 | 影棚柔光箱、纯白无缝背景、HDR、过度饱和、完美圆形高光、logo、图上文字 |

### 为什么不要字

1. **AI 写字最先露馅**，图上一出现规整排版，整张就变成「生成图」
2. 手机屏幕小，图上字和标题字抢注意力，读者两边都没读进去
3. 字用完就没法二次利用这张图（换标题要重做图）

> 需要大字时，用策略 B，而不是在照片上贴字。

## 策略 B：信息图封面（按需）

只适合**内容本身就是信息结构**的题材：图鉴、清单、参数对比、流程总览。

```
┌──────────────────────────────┐
│  {系列名} · NN/NN         ← 角标，右上，极小字
│                              │
│   {大字卖点 ≤ 12 字}         ← 最多 2 行，每行 ≤ 6 字
│                              │
│      [ 单一主体 ]             ← 占画面 55%–65%，只画一个
│                              │
│ {对象名} · {副标题}       ← 小字，不抢卖点
└──────────────────────────────┘
```

| 项 | 规格 |
|---|---|
| 大字字高 | ≥ 画面高度的 8% |
| 大字字数 | ≤ 12 字，2 行内，每行 ≤ 6 字 |
| 文字层级 | 大字 + 对象名 + 角标，**≤ 3 层** |
| 自检线 | 缩到 150px 宽仍能认出 4 个字 |

**注意**：策略 B 的文字必须**用排版工具渲染**（Pillow / Figma / Canva），**不要交给生图模型写**。模型写的字会缺笔画、间距失控。

## 两条策略都适用的

### 命名约定

```
assets/{编号}-{名称}-src.jpg     ← 生图或实拍原图
assets/{编号}-{名称}-cover.jpg   ← 裁成 3:4 的成品
```

### 尺寸与画质

- 平台要求「分辨率不低于 720×960」，推荐 1242×1656
- 生图 API 常见输出 864×1152（已是 3:4），够用；需要更大就用 `--width/--height` 或后期放大
- 上传格式 png / jpg / webp，单张 ≤ 32MB

### 第 2 页起（配方卡 / 要点卡 / 步骤卡）

首图负责点击，第 2 页起负责**留住人**（承接人均观看时长）。

- 第 2 页：本篇 3–5 个要点（配方／参数／清单／对照项），字号放大 1.5 倍，一行一项
- 第 3 页：3 条编号步骤，每条 ≤ 18 字，加一行「记住这一点」
- 第 4 页（可选）：数字卡，只在卖点含数字时用，**一批最多 3 次**
- 每页底部照抄档案的 `fixed.image_footer`

### 自检（发布前逐条过）

- [ ] 首图是照片还是信息图，与档案设定一致
- [ ] 策略 A 时：图上 0 字
- [ ] 3:4，长边 ≥ 1242
- [ ] 主体只有一个，能一眼认出是什么
- [ ] 没有 logo / 品牌 / 价格 / 平台水印
- [ ] 若主体是人：确认是实拍，不是 AI
- [ ] 缩到 150px 宽，还能看懂是什么
